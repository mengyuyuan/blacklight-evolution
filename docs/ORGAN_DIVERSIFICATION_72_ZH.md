# 黑光器官分化：72 种生物学设计

日期：2026-10-24。范围：先为 NeoForge 1.21.1 设计，Forge 1.20.1 随后移植。

**状态：72 项完整设计，正在分批实装。** `organs.1` 已接入感染宿主第一批 12 类（5 类旧入口、7 类新增），其余 60 项仍为设计；不能宣传成游戏已有 72 套模型或技能。实际作用、主角能力边界和验收方式见[第一批说明](ORGAN_FUNCTIONAL_BATCH1_ZH.md)。

完整条目见 [逐项目录](design/ORGAN_CATALOG_72.md)，机器可读版本为 [JSON 目录](design/ORGAN_CATALOG_72.json)。每条均记录生物学依据、独立作用、外形、所需支撑与使用代价；等级、颜色、左右副本、同类器官的重复来源不另算一个种类。

## 1. 设计单位与生物学边界

本稿的“器官模块”包含完整器官、具有独立作用的器官复合体和特化组织。肌腱、肌束等并非都属于同一解剖学层级，作为模组单位必须具有独立功能、空间和表达规则。一个模块不是一个简单的属性百分比。

真实生物学用于结构与分工：例如螳螂虾通过储能和释放机构放大打击，海鳝的咽颚承担猎物输送，绒蠕虫的黏液射流形成缠绕捕获。这些依据分别对应独立模块。[储能研究](https://www.nature.com/articles/428819a)、[咽颚研究](https://www.nature.com/articles/nature06062)、[黏液射流研究](https://www.nature.com/articles/ncomms7292)。

黑光跨物种重组、宏观骨刃、快速发育、感染建筑和战斗数值属于游戏扩展。文献并不证明现实中可以把任意物种器官自由拼合。来源表区分原始研究、基础教材入口和实现前还需补核的专门解剖问题；不把来源入口当作每个模型细节都已验证。

## 3. 同样取得六份器官，也形成不同生物

### 3.1 原宿主提供基础身体，器官改变功能结构

提取实际模型的中轴、关节、头部、前后肢、尾和翼根。未知模组生物按关节和比例推断，并允许数据包覆写；不能只给牛、蜘蛛、僵尸分别写死模板。

主导器官、来源解剖、原身体构型和已建立的承力/输运网络共同决定表达。需要区分直立、四足、多足、长轴、翼型、水生流线、柔性与固着殖群等构型。新增类型不意味着所有宿主统一长同一对刃、同一圈触须、同一排尖刺。

所有已取得器官的数据和作用都保留，可以继续增强、参与组合与分化。主导用于组织外形和动作的主次，不设置“只有一个器官能变强”的上限。内脏多数留在体内，以呼吸、脉动、伤口修复、供养和行为表达；不是在皮肤外挂 72 个肿块。

这些是组合目标，不是八个固定终局职业。原宿主、成熟度、受力方向和供体结构会继续造成差异。

### 3.3 连贯重塑

吞噬后先记录供体信息，再建立血管/神经通道与承力根部，随后扩大对应组织，最后展开武器或运动结构。共享同一变形场处理皮肤、器官根部、关节和覆盖层。

器官强度、成熟度与表型分别存储。成熟器官继续增强，后代或再次融合也会出现结构分化；不能每次都只增大头和背，也不能每帧用噪声重抽外形。结构分支一旦选择便稳定保存，变化通过成长和融合过程过渡。

## 4. 生理耦合与实际能力

每个模块定义输入、输出、空间需求与运行节律。例如：

- 储能器 + 肌束 + 重锤：肌束加载，锁扣保持，打击后复位。储能器本身不凭空提供持续力量。
- 丝腺 + 纺丝器：分别负责材料合成和出丝控制；丝线要有真实锚点、断裂、回收与占用结算。
- 气囊肺 + 主心泵 + 翼膜：分别承担通气换气、输运与运动。气囊参与通气，不单独充当气体交换器官。[鸟类呼吸](https://openstax.org/books/biology-2e/pages/39-3-breathing)。
- 毒液腺 + 毒牙/毒刺：生产与递送分开，攻击必须真正接触。黏胶、毒液、墨幕和腐蚀液分别对应不同作用。
- 神经冠 + 感受器 + 承力肢：不同感知通道引导对应行为；视觉伪装不同时屏蔽全部感知。
- 再生芽基 + 输运 + 储备：先封闭和维持，再重建。再生细胞来源和重建位置需要记录。[再生研究](https://publications.mpi-cbg.de/Kragl_2009_1409.pdf)。

宿主自带的基础生理功能提供默认支撑。没有取得专门心脏模块，并不意味着原来的活生物突然没有心脏；获得模块表示特化、扩容或新的功能。处理同类替代器官时采用分区、并联或主次表达，不把不同肺、肾或装甲的所有倍率相乘。

长期成长继续使用实际养分和有效模拟时间。输出和形态可以持续发展；有限数、实体预算、缓存和服务器预算负责运行安全。限制计算量不等于删除已继承器官或伪造最终生物学等级。

## 5. 来源、吞噬与六份进阶门槛

沿用当前规则：同一次活体吞噬仅有一个拥有者和一次结算。真正收到的合格成熟来源器官才增加器官份数，供体祖先的吞噬/取得次数不复制。重复类别继续融合与计数，独立记录“份数”和“不同类别数”。

**下一阶段至少实际取得六份器官**，同时保留现有成熟、强度、同化值和有效竞争经历要求。这次设计不会偷偷把六份改为六种，也不自动开启人形转换。72 类目录给后续路线更多组合，具体新路线的六器官配方应数据化、可审阅。

新感染体从适合其身体和生态的模块中建立主导路线，后续通过成熟、环境压力与真实吞噬分化。新增器官不能要求玩家一个个添加生物 ID；使用实际解剖、行为标签与可覆写的数据规则。任意移植适配仍需针对特殊渲染器与非标准生命机制验证。

玩家吞噬仍只结算一次基础生命、生物质和进化点，再按实际器官解锁样本。新样本不自动购买全部技能，不把 NPC 的长期器官强度上限塞进玩家现有三阶研究。

## 6. 数据与旧存档迁移必须先行

代码核对发现：`OrganResearch` 当前使用两个 `int`，每类两位，并以 `1023` 截取五类数据。72 类需要 144 位，继续按 enum ordinal 左移会越界和串位。必须改为稳定 ID 映射，如 `Map<ResourceLocation, OrganProgress>`，并提供旧五类位段的明确迁移。

`TissueCore.forSeed` 当前把随机值乘以 enum 长度。直接增加枚举项会重抽旧实体主导器官。迁移时先按旧五类算法还原并保存原生 `nativeCoreId`、原种子和当前表型；新实体再用扩展目录选择合适路线。不能以改哈希模数当成新增器官。

每类状态至少包含：稳定 ID、来源解剖、稳定表型种子、已整合/待整合强度、成熟工作量、完整性、表达位置与功能分支。来源份数与同化操作 ID 保持独立；未知 ID 留作兼容记录，不转换成随机器官，也不因为客户端缺资源就删除服务器数据。

## 8. 验收与服务器边界

每个器官必须具备：真实来源和获得过程、保存/恢复、客户端观察同步、发育中与完成形态、至少一个独立作用、动作收回或运行周期、资源负荷或空间支撑，以及可识别的宿主适配。只注册一个名称、贴一层皮或加一个属性，不算该器官完成。

同样的吞噬序列分别用直立、四足、多足、长轴等宿主做六次连续吞噬对照；还要给同一宿主不同供体序列做对照。每次保留第 1、3、6 次、相同机位、相同观察距离的截图和来源记录。不能只改变出生种子却让所有最终身体仍相同。

服务端控制命中、吸收、状态、繁育、分离、组织连通和收益。器官动画不逐帧发伤害，不绕开其他模组的真实死亡接受流程，不因客户端 LOD 删除游戏功能。局部检索共享预算，感知不强制加载区块，繁育不生成无预算的实体海。

每个宿主的器官记录最大为目录种类数，与吞噬祖先数量无关；模型按实际表达、共享承力和观察距离生成有界复杂度，缓存按实际使用延迟建立。初始网格、缓存和实体预算需实测后确定，不在本稿冒充性能已过关。

目录初稿只校验了数量、ID、独立机制、旧入口映射、来源引用和分批覆盖。旧五类的 581 项逻辑、32 项服务端及三类宿主六次吞噬记录属于上一阶段，不能挪作新 72 种的验收证据。后续 `organs.1` 第一批已完成实际能力接入，并通过 592 项逻辑、41 项服务端用例，以及三类宿主连续六次吞噬与七类新器官动作的原生客户端验证；具体边界见[第一批说明](ORGAN_FUNCTIONAL_BATCH1_ZH.md)，原始记录随试玩目录提供。其余 60 项尚未实装，未宣称全部 72 种已经通过游戏测试。
