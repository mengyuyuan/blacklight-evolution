## 新发现及修复

实体加入世界会同步调用其他模组的监听器。两个转换流程此前把“addFreshEntity 返回成功”当作整个过程的最终成功，漏掉中途重入、移除或资格变化。

| 流程 | 已复现的行为 | 修复 |
| --- | --- | --- |
| 感染转换 | 新宿主发布时复制了仍归原生物的装备，监听器可同时看到两份 | 发布的宿主先不持装备；成功提交时从原生物转交 |
| 感染转换 | 监听器移除新宿主，原流程仍删除原生物及其装备 | 发布后、返回库存后再次验证双方存活、维度、感染状态 |
| 感染转换 | 监听器再次转换同一原生物，生成两个宿主 | 原生物身份预约覆盖整个过程，finally 释放 |
| 粘液分离 | 躯壳发布时再次分离，留下两个躯壳 | 玩家身份预约覆盖整个分离过程，finally 释放 |
| 粘液分离 | 躯壳已经被监听器移除，仍进入无法返回该躯壳的粘液形态 | 躯壳存活、爆发状态与维度检查后才提交形态 |
| 粘液分离 | 监听器已关闭虐杀模式，原调用仍进入粘液形态 | 重新验证玩家状态对象、资格和动作条件 |
| 九头蛇喂养 | 猎物死亡事件被取消但血量留在零，仍增加喂养次数 | 只接受伤害返回成功、真实死亡已接受且击杀归九头蛇的猎物 |

新增三个 GameTest 类：六项用例调用真实 `EntityJoinLevelEvent` 监听器，另有取消猎物死亡与正常死亡的两个真实伤害链用例。七项负向回归分别在各自修复前失败，修复后通过；正向用例检查正常喂养仍增加一次。原生物装备、正常转交装备、躯壳数量及失败后的玩家形态都有实际断言。

没有新增存档字段或改变网络协议，没有改模型、动作、伤害数值或进化门槛。
