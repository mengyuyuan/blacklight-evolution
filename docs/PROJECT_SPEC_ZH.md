# Blacklight Evolution 项目规范

版本：0.2.0-mvp.5

基线日期：2026-08-08

目标：在 Minecraft Java 版中逐步复刻《虐杀原形》的核心战斗、变形、移动、吞噬、伪装与成长体验。

## 1. 技术基线

- Minecraft：1.21.1
- 加载器：NeoForge 21.1.244
- Java：21
- Epic Fight：21.17.3.1，负责玩家骨架、完整身体动作、动作分层、攻击阶段与碰撞时序。
- GeckoLib：4.9.2，负责生物质模型、利爪等变形覆盖层、感染生物、触须和关键帧特效。
- 构建命令：`gradlew.bat build --no-daemon`
- 测试命令：`gradlew.bat test --no-daemon`
- 开发启动：`gradlew.bat runClient --no-daemon`

禁止随意升级 Minecraft、NeoForge、Epic Fight 或 GeckoLib。升级必须单独建里程碑，并重新验证所有动画文件、Mixin 注入点、网络包和玩家渲染器。

## 2. 核心架构边界

### 2.1 服务器权威

以下结果只允许服务器决定：

- 感染状态、已解锁能力、当前形态、生物质、EP、伪装身份与警戒状态。
- 攻击命中、攻击距离、伤害、硬直、击退、消耗与冷却。
- 蓄力计时、最终跳跃速度、墙跑、滑翔和空中冲刺的物理结果。
- 吞噬目标、生命恢复、外貌/记忆获取和剧情推进。

客户端只发送输入意图并进行视觉预测，不得直接决定伤害、资源变化或永久状态。

### 2.2 动画职责

- Epic Fight 是玩家本体骨架的唯一主动画源。
- GeckoLib 只渲染生物质覆盖层和独立实体，不再建立第二套玩家身体骨架。
- 利爪必须挂在 Epic Fight 上臂/手臂骨骼链上，不能作为手持物品。
- 任何攻击都要拆成 `startup / active / recovery / cancel` 四段；伤害窗口由服务器的 `CombatAnimationSpec` 控制，不能由动画文件中的视觉关键帧直接授权伤害。
- 移动动画必须同时验证 Root、骨盆、左右大腿、左右小腿/膝盖、脚掌、躯干和双臂。只有 Root 位移而腿部不交替，不算跑步动画完成。
- 动画不得通过模型根节点持续平移玩家；真实移动由物理系统控制，动画只表现姿态，避免脚滑和服务器回弹。

### 2.3 网络与预测

- 输入包只传按键状态或一次性动作请求，服务器保存权威状态。
- 客户端预测必须使用与服务器相同的调参值；预测只负责画面平滑。
- 新增网络字段必须提升协议版本，并验证单人整合服务器和独立服务器。
- 不得每帧发送无变化输入；只在状态变化时发包。

### 2.4 模型与资源

- Blockbench 源文件使用 `.bbmodel` 保存，但不得打入发布 JAR。
- GeckoLib 模型导出到 `assets/blacklight/geo`，动画导出到 `assets/blacklight/animations`。
- Epic Fight 动画放在 `assets/blacklight/native_animations`，文件名与 Java 注册名必须完全一致。
- 左右模型必须独立调参，不能用一个镜像参数代替另一侧。
- 不分发《虐杀原形》原版模型、贴图、声音或其他受版权保护资产；所有资源必须自行制作或确认授权。

## 3. 代码组织规范

- `movement`：移动状态机、服务器物理、可调参数。
- `combat`：攻击状态机、阶段时序、伤害和碰撞。
- `power`：能力类型、解锁与升级定义。
- `state`：玩家永久状态和网络编解码。
- `network`：只放网络载荷与注册。
- `client`：输入预测、调试器、渲染、客户端动画桥接。
- `integration/epicfight`：Epic Fight 动画注册与兼容层。
- `mixin`：仅放无法通过公开事件实现的最小注入。

新增系统必须有明确状态枚举，禁止用多个互相冲突的布尔值拼出动作状态。公共调参集中管理并提供上下限，不允许在事件处理器里散落魔法数字。

## 4. 调试器规范

- `K`：利爪模型调试器；左右侧必须可分别调整位置、旋转和缩放。
- `J`：模型优先的透明动作时间轴；必须保持第三人称人物无遮挡，在人物上直接点选动画资源中的全部 20 根骨骼，提供位移/旋转/缩放三种变换模式。旋转应使用红 X、绿 Y、蓝 Z 的可拾取旋转球，彩色环优先于邻近骨骼点响应，支持球心自由旋转、单轴高亮、Shift 精调与 Ctrl 角度吸附；必须另有下蹲联动控制，一次拖动同步驱动根骨、躯干、双髋、双膝与脚端，同时仍允许逐腿微调。编辑器写入完整 P/R/S 关键帧，并支持任意时间播放头、关键帧标记、播放/暂停、逐骨骼清空与持久化。第三人称背影视图的 `_R/_L` 拾取点必须与屏幕右/左一致，不得镜像。编辑器还必须提供视角归位和当前动作整体还原，动作还原应保留一次可撤销快照；快捷键分别为 `Home`、`Ctrl+Shift+R` 和 `Ctrl+Z`。
- `F8`：移动引擎调试器；面板需半透明且不能遮挡主要模型。
- 调试参数保存到配置文件，并在确认后复制到 `config-presets` 作为版本化基线。
- 每次修改模型绑定或骨架后，都要用当前预设回归，不能重新靠猜位置。

## 5. 完成定义

某功能只有同时满足以下条件才可标记完成：

1. 代码可编译，自动测试通过。
2. 单人整合服务器中功能逻辑可重复触发。
3. 第三人称正面、背面、侧面均无明显穿模、脱节、后仰或脚滑。
4. 动画有完整起始、持续、释放/恢复过渡，不是一次性姿态或占位动画。
5. 服务器与客户端没有持续位置纠正、重影或状态抖动。
6. 用户完成实际画面验收。

“日志触发”“速度变化”或“能造成伤害”只能证明逻辑链路，不能单独证明动画完成。

## 6. 当前验收基线

截至 2026-08-08：

- 已完成：感染基础状态；生物质/EP 数据骨架；利爪模型独立左右调参；利爪变形粒子和基础三连击链路；地刺实体与基础伤害；蓄力输入、下蹲锁存、跳跃释放；移动调试器；基础客户端预测；疾跑泥土颗粒拦截。
- 部分完成：利爪动作仍需原创精修；移动物理已有框架，但墙跑、滑翔、空中冲刺未达到原版手感。
- 明确未完成：蓄力过程的完整动画；起跳与落地/地板物理动画；合格奔跑循环。当前奔跑表现是双腿一起平移，必须重做骨骼关键帧。
- 尚未进入完整制作：其余攻击形态、防御形态、视觉能力、吞噬/伪装完整流程、敌人、载具、Boss、剧情、记忆网、EP 商店和完整 HUD。
