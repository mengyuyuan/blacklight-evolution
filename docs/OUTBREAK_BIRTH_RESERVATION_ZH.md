# 共用出生名额的事件重入修复

本批继续推进总台账 3.3，仅 NeoForge 1.21.1，不改变器官数量、伤害数值、模型、动作或地图。

## 问题与行为

原先各生产者先检查人口，再调用真实实体加入事件，成功后才记录出生。NeoForge 的 `EntityJoinLevelEvent` 在实体出现在世界实体索引之前触发；监听器此时启动另一生产者，会同时看到最后一个空位。

`WorldOutbreakSystem.addScheduled` 现在将实际待加入生物预留在该维度的当前出生窗口中：

- 已成功出生数与待结算感染体共同占用窗口名额。
- 待结算身体占用维度感染体总量和相交的 96 格局部人口；另一个已加载街区仍可使用自己的局部空位。
- 城市普通居民也预留城市全体生物名额，但不消耗感染体出生配额。
- 世界分阶段生成、建筑核心和作者母巢经 `spawnAt` 进入同一事务；实体母巢的护卫与城市居民入口也使用该事务。
- 事件否决或监听器抛异常时，在 `finally` 释放尚未成功的名额；实际加入成功只计一次。相同实体无法重入自己尚未结束的加入流程。
- 发布入口验证世界边界与实际整身已加载区块；不会为这次生成请求加载远处区块。保留各调用者原有的支撑、碰撞、游戏规则和模拟范围约束。

预留只存在于服务器同步调用期间，不写成离线出生队列，不给每位玩家、每座城市或每个口单独补发预算。名额释放不等于抹去已成功出生的窗口计数；需要真实服务器时间进入下一窗口。

## 服务端验收

`E:/Blacklight-Completion-20261027/birth-budget-server-r3.log`：98 项必需实服用例全部通过。
其中包含前批 81 项、12 项本批真实事件/入口用例及 5 项既有加载成长、多人投瓶、共用人口和六次吞噬流程回归。

本批用例检查：

1. 实体索引尚不可见时，另一生产者不能取得同一个最后出生名额。
2. 实际待加入身体已经占用维度人口上限。
3. 近处受局部上限限制，远处已加载街区仍可正常生产。
4. 真实事件取消后，名额与人口预留都退回，同一窗口可接受一次正常出生。
5. 同一实体不能递归加入或对已存在实体重复记账。
6. 等待真实服务器时间后，下一窗口恢复出生。
7. 未加载地点的发布请求不生成区块、不花名额。
8. 真实监听器抛异常后没有永久占位；日志中的隔离夹具异常为预期测试输入。
9. 真正的实体母巢护卫与世界生成，在两个回调方向都不能重复取得最后名额。
10. 世界生成回调里启动真实作者母巢时，被拒绝的母巢保留材料和育成工作。
11. 城市居民在真实加入回调中也占用全体生物上限。

第一批 7 项重入验证通过。第二批加入额外实体模拟距离限制，95 项中误拦两个已加载出口夹具；撤掉该额外限制后，保留整身已加载检查，第三批完整 98 项通过。

生产配置完整构建见 `birth-budget-build-r1.log`：750 项单测通过，无失败、错误或跳过，交付不含测试源码。

## 边界与剩余目标

本事务约束本模组的定时生产入口；不改写其他模组直接召唤实体或管理员指令的全局语义，也不把感染替换、读档恢复当成额外出生。

这只完成共享出生/人口预算的重入缺口。建筑各自育成工作的回调保护由后续 `BUILDING_ORGANISM_ZH.md` 补齐；自然资源输入、核心之间的实际流通、多城和默认日龄生态等仍在总目标内。
按 2026-10-27 用户纠偏，当前供养与孵化指附着建筑的组织生态；独立实体母巢只保留兼容，不以扩展其战斗波次代替建筑组织。
器官继续为 35 / 72；不据此勾选整个 3.3 或总目标。
