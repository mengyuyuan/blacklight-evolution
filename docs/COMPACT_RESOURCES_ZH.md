# 城市生成与包体缩减

2026-10-26 的默认发布包使用 `data/blacklight/city/generation.json` 中的
`geographic` 配置，不再分发洛杉矶全市的预生成方块档案。

## 保留什么

- 深圳和洛杉矶现有的冻结 OSM 地理瓦片、道路、建筑轮廓与地图中有记录的高度。
- 同一套经纬度投影、城市范围和 32 米采样的地形高度网格。
- 福田市民中心和洛杉矶市政中心的详细方块场景。
- 黑光维度入口、往返、感染与城市生态、已有技能和动作。
- 已生成并保存在玩家存档内的区块。此更改不会重建或删除它们。

普通街区按地图轮廓生成楼体；墙面、门窗、楼板、屋顶和无实测数据的高度使用
确定性规则。道路和建筑位置不依赖随机世界种子。这保留的是现有地理数据精度，
并不声称实景的每扇窗、室内陈设或每个方块均被测绘还原。

## 与全方块版本的区别

旧版将 Arnis 生成的全市约 534 万区块直接装进 JAR。原档案约 5.29 GB，
按列编码并逐方块核验后仍约 2.87 GB。默认包改用约 84 MB 的洛杉矶地理瓦片
和约 20 MB 的深圳地理瓦片，在游玩时只生成所需区块。实际包体以发布目录
的版本校验和验收记录为准。

新生成的普通楼体细节会与旧全方块版本不同；旧区块与新生成区块的交界可能
出现材质或楼体细节差异。查看新生成效果建议使用新测试地图。

完整原档案、压缩器和逐方块核验工具仍保留在开发源目录，默认发布任务明确
排除 `city/los_angeles_full/` 和 `city/los_angeles_compact/`。资源缺失不会被
当作自动切换生成模式的理由：`archive` 模式仍要求完整档案。

## 动作资源

254 个动作及配置文件使用无损 BJC2/XZ 存储，加载时恢复原始字节，并验证原始
SHA-256。没有裁减关键帧、降低采样率或改变数值精度。XZ 为纯 Java 内嵌依赖，
玩家无需额外安装解码库。原始动作文件及其来源声明保留。

## 地图混合压缩

compact.2 的正常构建使用纯 Java `CompactMapPacker`，逐个比较 Gzip 与 XZ 在 JAR
中的实际压缩占用，只对更小的文件切换格式。逻辑地图名、索引、投影和全部解码后
字节保持一致。运行时由 `MapResources` 解析逻辑名字；损坏的新格式会报错，不会
悄悄切换到另一份数据。字典内存仍受 4096 KiB 上限约束，每文件输出最多 8 MiB。

`verifyCompactMapResources` 对实际 JAR 中全部地图逐字节复核，并拒绝同一资源的
两套压缩格式同时混入。默认 `assemble` 同时运行地图、动作和 200,000,000 字节的
主 JAR 预算检查；资源分类和最大文件报告位于 `build/reports/package-size.json`。
如内容规模有经评审的变化，可显式设置 `-PpackageSizeBudgetBytes=<字节数>`。
此预算不以降低地图精度、裁掉动作帧或缩小贴图为默认解决办法。

## 验证与构建

正常 Gradle `processResources` 根据生成配置过滤地图档案，`jar` 内嵌解码库。
`tools/package_release.py --verify-only --directory-only --profile bundled --output <目录>`
校验实际安装文件夹、生产代码、冻结地理资源、精做核心和逐字节恢复后的动作。
验收还检查地图核心与外围道路和楼体生成、实际客户端进入两座城市及返回、
退出重进后的存档状态。游戏内无需下载地图或在线访问 OSM。
