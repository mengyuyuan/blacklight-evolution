# A 哥独立骨架与黑光动作接入

这次使用确认后的 Sovereign V4 方块模型：221 个方块、1024×1024 贴图。保留原来的体型、方块尺寸、细节和 UV，不再把身体拉宽或缩短腿去迁就黑光旧骨架。翅膀不在本次人物包内。

## 新骨架

人物使用独立的 35 个骨骼。躯干、上下臂、手部挂点、上下腿、脚、头发、眼睛、眼皮、眉毛、嘴部和三段衣摆分别保留节点。衣摆骨骼属于上身，便于后续追加衣物摆动；当前不宣称已有布料物理。

`MercerRig` 接收黑光最终采样姿态，按新骨架的关节位置重定向旋转和局部位移。基础移动、跑酷、攻击、变形、抓取和吞噬仍由现有黑光状态机与动作时钟选择，不新增第二套战斗状态机。技能的服务器伤害、目标判定、资源消耗与动作文件均未修改。

身体、武器和手持物使用同帧计算的挂接位置；抓取、吞噬和举起方块时保持原有手部交互位置。战甲生长时向现有战甲挂接位置过渡，并沿用现有身体遮挡规则。眼皮用玩家 tick 和部分帧插值驱动，不保留跨重生的实体动画缓存。

## 游戏中启用

1. 使用对应 Minecraft 和加载器版本的 `mercer.1` 黑光预览包，替换旧黑光 JAR；不要同时放两个黑光 JAR。已有必要前置按当前版本保留。
2. 进入黑光感染/能力模式后按 **J**。
3. 点击左上方 **“外观：玩家皮肤”**，切成 **“外观：A哥 · 黑光动作”**。
4. 点击“完成”回到游戏。再次点击同一按钮可以恢复玩家皮肤。

外观选择保存于 `config/blacklight-appearance.properties` 的 `mercer=true/false`。默认关闭，仅作用于本机角色，不强制替换其他玩家，也没有新增外观同步协议。

## YSM 文件与黑光接入包的区别

- `Alex-Mercer-Blacklight-V4.1-YSM.zip` 是独立 YSM 人物包。解压后把 `alex_mercer_blacklight` 放入实例的 YSM 自定义模型目录（通常为 `config/yes_steve_model/custom/`），通过 YSM 选择该模型。
- YSM 文件包含同一套 35 骨骼模型、基础动作、表情层，以及 240 段从本项目现有动作适配到新骨架的 `blacklight_*` 编辑预览动作。它们沿用项目现有动作及修改记录，不是新宣称原创的 240 段动作。
- **单独放入 YSM 包不会自动识别黑光技能状态。** 技能状态和人物姿态的实时连接由本次黑光 JAR 的原生渲染适配层完成；感染模式中启用 J 外观后使用该连接。YSM 本身不是这层适配新增的强制依赖。
- 普通第一人称手部继续走现有手部/YSM 渲染，能力武器继续走黑光第一人称路径。本次没有重新制作第一人称技能动作。

## 可编辑源文件与重建

- `art/mercer-v4/layout.json`、`alex_sovereign_v4.bbmodel`：原始 V4 几何，保留作对照。
- `art/mercer-v4/mercer_blacklight.bbmodel`：独立 35 骨骼的可编辑版本。
- `art/mercer-v4/blacklight-rig.json`：骨骼映射与动作列表。
- `tools/export_mercer.py`：标准 Python，导出原生网格与新骨架，不改变原比例。
- `tools/retarget_mercer_ysm.py`、`tools/mercer_rig_math.py`：Blender Python，输出 YSM 包到 `build/mercer-ysm/`。

在仓库根目录执行：

```text
python tools/export_mercer.py
blender -b --python tools/retarget_mercer_ysm.py
```
