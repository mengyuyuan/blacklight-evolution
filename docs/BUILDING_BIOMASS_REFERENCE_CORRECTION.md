## 外观差异与后续实现要求

- **主体有完整体积**：单个粗柱贯穿多层楼，斜向撑出楼面，横截面远大于人；不是把每格墙皮加厚一点。具体 MC 尺寸需根据测试建筑比例设计，不冒充原作精确米数。
- **轮廓不规则而连续**：收腰、鼓包、拱起和分叉沿同一大形连接。避免等粗直圆柱、均匀条纹、重复立柱以及小肉球堆砌。
- **层级清楚**：少量主柱占据主体轮廓；分支从主柱汇合处分出；细根和肉膜负责把大体积结构融入原建筑。墙体要有露出的空隙。
- **材质有肉质层次**：暗红/褐红的大块肌束，黑色坏死外皮，局部鲜红裂隙；不把整栋楼铺成高亮红条纹。
- **生长体现体积变化**：先根系/局部附着，随后主柱逐段增厚延展，再膨大分叉。阶段改变不能瞬间把整栋楼替换掉。

现有 `growSurface()` 只接受有相邻坚固支撑的表面位置，附件模型最厚约 0.73 格，因此无法产生实机参考的伸出墙面的巨大柱身。这是生成形态的限制，不是光影不足。

后续需将立体主干/分支的生成与薄层表面附着区分处理，并继续共用维度工作预算、区块加载检查、存档恢复和核心清除逻辑。不能用每 tick 大范围填充或实体堆叠来换取体积。

验收应在同一个楼体上，以玩家作为尺寸参照，检查远景轮廓、侧面厚度、近景材质与阶段变化；已有单元测试/服务端测试通过不代替此项美术验收。
