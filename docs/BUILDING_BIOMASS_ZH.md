# 立体建筑血肉柱（NeoForge 1.21.1，2026-10-23）

本轮把原有贴墙感染扩展为真正占据空间的柱体、分支与地面根系。参考二代红区巨型血肉支撑的轮廓，以及本模组粘液爆发已有的真实方块锚点；未导入二代建筑网格。

## 活体行为与外形

- 延续感染核心的附着、扎根、占据、成熟四阶段。组织逐段伸展、增厚，成熟后生产感染者和猎手。柱体有实际碰撞；不是整栋建筑变成移动实体，当前柱身没有持续蠕动动画。
- 根据世界种子、核心位置、墙体高度和有效支撑生成持久的结构。包含单一倾斜主柱、不对称分叉、外拱支柱与三向冠等骨架，主柱数量、尺寸、弯曲方向、分支出口和生长时序各异。不会每帧或重进世界重新随机。
- 常规主柱直径约 3–8 格，随可用楼面高度和结构变化；膨大处可以稍宽。墙面必须有真实支撑才有分支终点；近地面还会向可用街道方块扎根。每个核心最多 8 条连续路径。
- 如果街道对面或斜对面 8–30 格内有有效楼面，会从主柱伸出下垂的粗索连接邻楼。两端都依赖真实支撑，另一栋楼的支撑拆掉后连接也会失效；不会为了寻找邻楼加载新区块。
- 几何使用共享格点的连续截面并合成一体，避免堆叠大量独立肉球。表面仍为 Minecraft 尺度的棱面；保留正常方块光照，并混合已有暗红肌肉、黑色外皮和纤维材质。
- 原建筑、箱子及其内容保留。组织只进入空气或替换原来的薄层附着物；没有把整栋楼替换成血肉。成熟根系挡住原孵化出口时，会寻找两侧安全地面。

## 破坏、保存与同步

路径、实际支撑坐标、生长游标、断裂分支和玩家已挖除的位置随维度数据保存。移除锚点会停止其主干及从属分支，并由同一工作队列逐步清除失去支撑的体积。挖掉一格不会马上长回来；摧毁核心停止继续生长和生产，已生成的组织留在世界中。

服务器通过普通方块更新同步。每维度原有的共享工作预算同时负责贴面、体积和成熟处理，没有每根柱子一个持续渲染实体，也不强制加载区块。可见表面和碰撞来自同一截面场；相邻方块、区块使用一致边界。

自然放置的柱体会发布可取消的 `EntityPlaceEvent`，被拒绝的位置恢复原状态且不重复尝试。该测试只证明标准 NeoForge 事件能拒绝体积放置，不宣称兼容所有领地插件；旧贴面逻辑也不因此自动获得所有第三方保护兼容。

## 设置与预算

`serverconfig/blacklight-building-infection-server.toml` 中新增 `buildingBiomass=true`。关闭后停止柱体更新，已有方块保留；`buildingInfection`、`mobGriefing` 和核心清除仍控制整体流程。

- 默认每维度每 5 tick 处理 4 项工作，贴面与体积共用。
- 每核心最多 16,384 个体积候选单元；计划生成时拒绝超过预算的结构。
- 每块最多 12 个表面三角形，256 种截面各用三种材质在模型烘焙时缓存。内部实心单元不生成隐藏表面。
- 上述预算限制存储与渲染增长；不等于已证明大量殖群在所有电脑上都不卡。尚未完成多人长期压力测试。

## 玩家入口

用 1 个活性母巢组织与 3 个腐肉合成黑光建筑感染核心，放在靠近地面的建筑外墙。测试取物指令：

```mcfunction
/give @s blacklight:building_infection_core
```

成长只计算区块实际模拟时间，默认至少十分钟达到成熟时间门槛，还需足够表面成长与队列处理。自然感染组织贴近有效建筑时也可建立核心。完整核心流程和设置见 [建筑感染](BUILDING_INFECTION_ZH.md)。

这次同时整合原先只在本地工作区的持续器官进化、猎食和吞噬研究代码。Forge 1.20.1 的完整进化/建筑系统尚未随本轮移植。
