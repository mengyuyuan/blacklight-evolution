# 感染初次继承与残血吸收保护

## 已定范围

只调整初次感染继承及高原生战力的识别。无限进化的公式、代数、器官、玩家属性强化和进化者倍率保持原样。
旧《感染强度调整草案》中削减无限成长和进化者生命倍率的建议已被用户否决，本次不采用。

## 初次感染继承

`blacklight-gameplay-server.toml` 的 `[infectionStats]` 控制：

- `enabled=true`：启用分段继承；关闭后恢复旧的初次 1.4 倍生命、1.3 倍原生攻击算法。
- `highHealthThreshold=1000`、`ordinaryHealthBonus=0.4`、`excessHealthBonus=0.05`。
- 生命 = 原生生命 + 阈值内部分 × 40% + 超出部分 × 5%。连续计算，越过阈值不会突然变弱，也没有固定生命上限。
- `highHealthUsesNativeUnits=true`：原生生命已达阈值的生物及其转换宿主保留原生 HP 单位，不再额外乘通用五倍显示单位。
- `highAttackThreshold=100`、`ordinaryAttackBonus=0.3`、`excessAttackBonus=0.1`：原生攻击按同样的连续分段方法继承，保留低攻击宿主原来的最低咬击规则。
- `recognizeNativeCombatStrength=true`：高原生血量／高攻击感染体使用已有的精英对感染玩家接触伤害预算，不再一律按普通小怪的 10 HP 上限处理。不会强行抬高低伤害。

原生生命 20、1000、10000、1000000 时，初次生命基础分别为 28、1400、10850、1050350。原生攻击 10、500、50000 时，基础继承分别为 13、570、55020。
这里的“原生”指扣除黑光通用五倍单位后的转换来源实际属性，仍包含来源当时的合法属性加成；原生感染药效原有的 +6 生命等加成没有移除。
普通低血量来源继续保留旧的五倍生命显示及同步伤害换算，例如 20HP 来源转换基础为 28，显示为 140；高血量来源采用原生单位。基础曲线连续，切换单位前后的可见血量数字不能直接比较，应连同伤害换算判断实际耐打程度。

高数值攻击不再被宿主的原版 2048 属性读取上限截断；仅在黑光宿主内部按原版属性运算顺序重算，保留后续获得的加成。没有更改其他模组或原版生物的全局属性上限。
初次继承与后续成长分开保存：一个低血量来源靠无限进化长大，不会因为后来超过 1000 血就重新压缩成长或切换单位。
已有宿主按保存的原生属性重新计算，保持剩余生命比例、器官、代数与成长记录；重复加载不会叠乘初次感染增益。没有来源数据的指令样本及专用巨型 Boss 保留作者配置。

## 一次残血保命

同一配置的 `[consumeLastChance]`：

```toml
[consumeLastChance]
enabled = true
healthFraction = 0.15
```

受击前已在 15% 生命线内、属于可吸收类型的生物，被已感染玩家或其有明确归属的投射物打出致命伤害时，首次留 1 HP。
之后继续攻击仍能击杀；不是持续锁血。满血及高于阈值的一击击杀正常结算。非致命或被取消的攻击不消耗机会。
使用次数随实体存档保存，感染转换也会继承，读档或变成感染宿主不能刷新次数。保护由服务端统一判定，多个玩家共享同一只生物的一次机会。
正常吞噬和死亡粘液吸收的最终处决显式绕过该保护；环境伤害、普通未感染玩家、虚空和管理指令不触发。不可吸收、驯服、种植的传送九头蛇等继续服从原来的吸收资格。
成功保命没有死亡收益；之后实际死亡才支付一次配置比例的击杀资源；吸收则保留全额资源和原有附加收益。
该机制监听标准伤害／死亡事件，不能保证拦截其他模组跳过事件直接删除实体的做法，也不覆盖用代码直接改血后另行删除实体。

## 配置位置

服务器配置名为 `blacklight-gameplay-server.toml`。通常位于单人存档或专服世界的 `serverconfig`；部分启动方式（包括本轮 NeoForge GameTestServer）会放到运行目录的 `config`。
以实际生成的同名文件为准。所有配置由服务端决定；建议停服／保存退出后编辑，并重启让所有宿主完成迁移。只修改客户端文件不会覆盖服务器设置。
