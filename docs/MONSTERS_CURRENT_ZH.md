# 当前黑光怪物与大型生物：源码说明

以下为2026-10-24本地源码核对，描述已有实现，不表示本轮又新增了这些怪物。军方和黑色守望是军事人员，此处不算作感染怪物种类；投射物、视觉壳和地刺也不按完整怪物重复计数。

| 体型/类别 | 已有内容 | 简单理解 |
| --- | --- | --- |
| 常规感染体 | 黑光感染体，外观来自感染前的人形或动物宿主 | 一个自定义感染宿主实体可承载多种原版生物的外观与感染变化；不是每种外观都注册一个新实体ID |
| 小至普通体型 | 黑光潜猎者、黑光喷吐者 | 专门的感染变种，拥有各自行为 |
| 较大体型 | 黑光猎杀者·重爪、黑光重甲兽 | 接近人形或兽形的大个体，不能等同几十格高的巨型Boss |
| 大型/成长分支 | 黑光蜂巢、九头蛇、巢生吞噬者 | 蜂巢为固定巢体，九头蛇有成长缩放，吞噬者是感染宿主的成长身份分支 |
| 巨型Boss外形 | 监守者、铁傀儡、凋灵、末影龙的感染巨型档案 | 以原版物种为来源身份，但采用模组自己定义的巨型外形、行为与命中部位 |

所谓多种宿主“外观覆盖”不等于同样数量的独立怪物注册项，也不能把每个成长阶段重复算作新怪物。具体生成、成长和战斗可见性还取决于配置、地点及玩法进度。

## 大型怪物怎么实现

Minecraft提供实体系统、寻路、伤害、网络同步、方块世界等基础能力。黑光的感染宿主继承这些基础类，再写自己的感染状态、成长、攻击和渲染。

普通宿主可以借用原版物种的外观，再叠加感染表现；巨型Boss使用自定义模型/网格和Boss档案。大模型需要让玩家能击中不同部位，代码用 `InfectedHostPart` 分部位实体，接入Forge/NeoForge的多部位实体接口；这是模组自己的实现，不需要另外安装巨兽模组，也不只是把普通僵尸的显示比例拉大。

“来源身份是监守者/铁傀儡”等，指设计和数据来源；不代表其巨型战斗、模型或碰撞直接由原版完整提供。场景里的巨大蜂巢建筑则属于世界生成结构，不能当作一只会移动的巨兽。

## 主要源码位置

- `registry/ModEntities.java`：专用怪物实体的实际注册。
- `entity/BlacklightInfectedHost.java`：感染宿主及多部位接口。
- `entity/InfectedBossProfile.java`：四类巨型Boss档案与尺寸设计。
- `entity/InfectedHostPart.java`：巨型部位与伤害交互。
- `client/renderer/InfectedHostRenderer.java`：普通宿主代理外观与巨型自定义网格渲染。
- `world/ColossalHiveLayout.java`：巨大蜂巢建筑布局，属于世界结构。

上表只说明代码已有类别与实现方式，本轮军官验证没有将所有感染怪物的客户端战斗效果重新验收一遍。
