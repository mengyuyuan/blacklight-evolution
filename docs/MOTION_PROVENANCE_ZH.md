# 动作的初始来源与本项目修改

当前动作库是 Blacklight 项目长期修改、调试和适配后的版本。初始来源记录与当前动作的制作工作应分开描述，不能看到 `Original-derived`、原版动作名或旧的 `privateNotice` 字段，就将当前整套动作判定为“未经修改的原版动作”。

## 元数据含义

- `provenance.currentStatus = project_modified_and_adapted`：本项目修改与适配版本。它不表示每一帧都经过修改，也不是逐关键帧的作者归属统计。
- `source`、`sourceSha256` 等既有字段：保留初始输入的名称、哈希、帧段和技术记录。原版数据转换的初始来源与后续修改可以同时存在。
- `privateNotice`：为兼容已有打包工具而保留的历史字段名。内容已改为本项目修改状态及初始技术背景，不再表示“仅限本地”或“禁止打包”。这个字段本身不是当前许可或发布状态的判据。
- `provenance.authorshipScope`：记录本项目的修改与适配，不将其自动等同于“所有关键帧从零手写”。

本次依据维护者对长期修改工作的确认，更新现有动作库的项目制作状态。没有对每一帧重新做来源比对，因此不能据此计算“有多少帧原创”或“有多少完整动作完全重写”。反过来，仅统计旧来源标记也不能得出当前有多少动作仍是未经修改的转换结果。

## 制作与维护规则

修改动作时，应在提交记录中写清修改的轨道、姿态、衔接、时序或适配内容。完全重写动作时，应同时留下可编辑源文件与生成方式，按证据更新该文件的来源说明；不要批量宣称全部原创，也不要用起始来源抹去后续制作工作。

`tools/motion_provenance.py` 统一现有转换导出器的说明方式，区分起始数据和项目适配，避免重新导出时恢复过时的本地构建文案。独立创作的动作不应套用这组初始来源信息。

## 本次修改范围

仅更新说明字段与文件校验清单，并同步导出器、资源说明。本次不改关键帧数值、骨骼、动作时长、伤害窗口、位移、镜头参数或玩法代码。资源文件的 SHA-256 会因说明文字改变而更新；初始 `source` 哈希保留，不与资源成品哈希混淆。

本页说明制作记录和元数据含义，不新增、删除或代替项目及第三方许可证。
