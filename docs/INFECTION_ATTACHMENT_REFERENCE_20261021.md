# 附着物增生参考与需求纠正

## 用户确认的目标

附着物在宿主身上持续随机生长，逐渐覆盖整个生物；增生必须形成变大的立体器官，不能止于铺一层黑皮。用户进一步确认，宿主本身也要在过程中发生局部异变，例如组织膨大、肢体拉长和轮廓改变。骨骼动作仍要保留，不能用等比放大全身代替这些变化。

已撤回实验性的 HostGrowth、整体碰撞箱放大、成长属性修饰和专用步态混入；该实验的截图和旧测试日志不代表当前附着物实现的验收。

## 实际查看的 Spore 源码

作者仓库：https://github.com/Entity442/Spore_1.21.1_neoforge

本地只读参考：E:/Blacklight-Infection-Research-20261021/spore-reference

固定提交：762ccf754773d051e2a478ff090d1a68056811ee。它是所查作者仓库的 HEAD，不声称与本机 2.2.0j 发行包完全同版。

- Sevents/Infection.java 的 onEntityDeath：在服务端处理感染死亡转换，配置/JSON 指定目标实体，生成感染形态并移除原实体。
- Sentities/EvolvingInfected.java：每秒检查进化点和计时条件，满足后选择进化目标并生成新形态，传递名称、击杀点、进化点和群体连接等状态。不是把所有外观变化实现为全身缩放。
- Sentities/BaseEntities/Infected.java：通过 SynchedEntityData 同步进化值，将 hunger、kills、evo_points、evolution、linked 等写入 NBT。
- Client/Models/InfectedPlayerModel.java：头、下颌、躯干、四肢是明确的模型部件，局部组织与部件层级共同制作。
- Client/Layers/CalamityRoots.java：根据 rooted 状态绘制专用根系模型。
- Client/Layers/CalamityVeins.java：复用父模型绘制带变异色的附加层，覆盖层自然使用同一模型结构。
- Sentities/VariantKeeper.java 和 BasicInfected/InfectedPlayer.java：变体 ID 是实体状态的一部分，会同步并保存，不依赖每帧重新随机。

这些文件可参考状态保存、部件绑定、分层和变体组织方式。所查路径没有发现能够直接移用的“任意第三方模型表面自动连片增生并长满全身”通用引擎，不应将本项目的新算法描述成 Spore 原有算法。没有将第三方源代码或模型复制进黑光发行资源。

## 覆盖与攻击基础

下列记录包含早期器官版。用户随后否定其放射状长刺与拼接外观；当前造型改为连通的胸肩/肋侧增生及组织裂口，见 [造型修订](TISSUE_ART_REWORK_20261021.md)。不能将旧版测试通过等同于造型已获认可。

- 原来的单面小筋腱改为实际 ModelPart.Cube 六个面的表面增生。
- 每个立方体表面有 24 个相连生长区域；先从一个随机种点开始，每个后续区域与已生长区域相邻，逐步连成覆盖层。
- 随机顺序由 UUID 和模型局部几何确定。使用有限的预计算布局，不在每帧重新抽签，不随观察者变化。
- 躯干优先，头和肢体有少量错开；最终所有被渲染且符合尺寸条件的部件都可覆盖，接缝处跟随各自骨骼动作。
- 连续薄层是器官与宿主的连接组织，不是最终形态。此前只做小突起的覆盖版本不算本需求完成。
- UUID 决定固定成长轨道与主导侧。胸肩、背部和肋侧是同一个连通体积中的区域，触须从组织裂口展开；人形可有额外前臂刃。器官随保存的成长值发育，不生成堆叠方块或额外附着物实体。
- 躯干和头部逐渐增厚，一侧主导上肢出现不对称肥大；人形主导上肢还会拉长。四足动物的支撑腿保持落脚高度，主要增厚。变形仅作用于当前模型部件的编译矩阵，皮肤、伤口、已有专属模型和附生器官共用该矩阵，不写入共享模型骨骼。
- 成熟触须有独立服务端攻击：8 tick 蓄力，12 tick 接触，28 tick 收回；在命中时复核距离、视线和目标存活，只结算一次普通生物伤害。目标离开、墙壁阻挡、宿主受吞噬或硬直时不能穿墙命中。攻击目标和起始时间同步客户端，临时攻击不保存进存档。
- 成长不整体修改生命属性或导航碰撞箱；延伸攻击距离与第一个触须的长度使用同一成长规则。旧巨构与供养者继续走自己的角色和模型流程。
- 不新增大量附着物实体。单次绘制最多捕获 32 个可见部件，每部件最多两个有体积的 Cube，最多处理 768 个表面区域。极复杂第三方模型超过预算时覆盖不保证完整；薄平面和完全自定义骨骼需要独立适配。

这些是本模组的实现选择，不冒充原作或上述模组的精确机制。
