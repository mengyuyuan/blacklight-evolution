# 子弹俯冲：高度、材料与流式地形冲击

dev.10 将真实 Minecraft 破坏／掉落与每 tick 性能预算分开。原作没有 Minecraft 方块，以下坑形、材料成本和保护规则均为方块玩法适配。地形任务完全由服务端拥有，客户端只接收方块变化、破碎反馈和正常物品实体同步。

## 高度计划

输入为同一次俯冲真实最高 Y 与实际落地 Y 的差。负数归零，NaN／无穷视为无效输入；没有 512 格高度上限。6 格及以下不破坏，超过阈值的高度记为 `e = height - 6`。

| 量 | 计算 | 含义 |
| --- | --- | --- |
| 半径 | `2 + floor(sqrt(e * 0.5))` | 理论圆形影响范围，随高度持续增长 |
| 中心深度 | `1 + floor(cbrt(e))` | 理论碗状坑中心深度，随高度持续增长 |
| 能量 | `e * 8` | 实际可用于破坏材料的总能量 |
| `Plan.budget` | `floor(energy)` | 硬度为零、每块最低成本为 1 时的理论数量；不是访问候选的截止数 |

取消了原先半径 12、深度 10 和总数量 4096 的截断。整型半径／深度、long 数量和 double 能量仅在 Java 数字表示极限饱和；普通世界坐标与真实游戏高度远低于该极限。实际能量不会由每 tick 的性能预算截断。

距离平方使用 long，平方前检查各轴与半径，避免整型平方溢出。越靠近外围，列深度按 `ceil(depth * (1 - distanceSquared / radiusSquared))` 递减，圆边界外不产生候选。材料成本为 `1 + hardness * 3`；局部强度随高度增加、随径向距离及深入层数降低。实际破坏消耗剩余能量，空气不消耗能量。

## 只流经已加载环境

冲击从落地点所在区块出发，用不会加载区块的 `getChunkNow` 检查四邻接区块。未加载区块不继续向外传播，也不会跨过未加载空隙跳到远处玩家加载的孤岛。每次流步骤只进行一次区块检查或取出一列；已加载区块每项最多保存 16×16 个列位置，深度逐层生成。没有预先分配整座 `radius² × depth` 坑，也不扫描理论大半径内全部未加载坐标。

区块前沿和各区块下一列使用距离优先队列，正常连续加载区域中的列按距离从近到远处理。完成的列与区块立即退出前沿；去重只记录实际到达的已加载连通区域及其未加载边界。内存和空探测数量随真实加载环境变化，而不是随理论高度对应的整个坑体积增长。

因此，理论半径可能大于本次实际坑：当前加载范围、世界建筑高度、材料、玩家权限和保护事件都可以缩小实际破坏范围。这些是世界环境限制，不是高度或能量上限。开始时没有加载的冲击区块不会被强行加载；处理期间再次检查区块与方块状态。

## 保护与分批处理

基岩／负硬度保留；每个候选遵守玩家交互权限与真实 `BlockEvent.BreakEvent`。事件由本任务明确发布，因为 `Level.destroyBlock` 本身不会替玩家发布 mining `BreakEvent`。线程局部只标记这一个确切事件，用来避开 Blacklight 自己的普通挖矿锁，不绕过其它模组或服务器保护。事件之后再次检查玩家、开关、维度、区块、权限和原方块状态，避免事件回调改变状态后仍毁块。

移除以前对容器／全部方块实体的统一排除，也移除 `resistance >= 1200` 的固定保护：黑曜石等正硬度、可挖的高耐爆方块，在真实高度足以克服硬度和材料成本时可破坏。负硬度仍不可破坏。被权限／事件保护、硬度超过局部强度或未成功破坏的实体方块会停止该列，保留下方支撑；不通过掏空下方绕过保护。

全局每 tick 最多进行 **192 次候选／区块流步骤、32 次成功的真实破坏**，并设 **3ms 工作时间预算**；所有玩家共用这一个预算，活跃任务轮转分配工作。32 是破块调用上限，不是掉落物数量上限：一个容器可能产生多个正常物品实体。预算到达后原任务保留能量和流式游标，下 tick 继续，不把剩余块改为空气或偷偷取消掉落。

计时在候选开始前检查。一次原版毁块、loot／容器回调、邻居更新或外部保护监听器是不可中途拆开的同步操作，可能让该次调用越过 3ms；调用结束后不再开始下一候选。这是每 tick 的合作式工作预算，不是对其它模组同步回调的硬实时中断。32 次真实毁块可降低实体和网络的瞬时峰值，但不会限制最终正常掉落总数；高落差大坑仍可能跨多个 tick 完成，真实物品也会在世界累积。低 TPS、大容器和联机网络下的实际性能须用服务器测量，不用算法测试冒充实机报告。

每位玩家 UUID 同时最多一个活跃地形任务，新有效俯冲会把旧任务标为 `superseded` 并替换。旧任务的结束回调只能移除自己的活跃槽，不能误移除新任务；这防止同一人连续会话积累无界任务。它是新攻击主动覆盖旧攻击，不是性能预算按高度削减威力。没有原先 `MAX_ACTIVE=16 / queue_full` 的直接放弃新任务规则；活跃槽规模随在线玩家数变化，结束后的历史 snapshot 有限保留。

没有单任务 10 秒／30 秒截止，没有 4096 块总截止。任务在能量耗尽、可到达环境处理完毕、新攻击覆盖、显式取消、开关关闭、玩家死亡／离线／换维度等情况下结束。

## 真实掉落与容器路径

所有成功破块仅调用一次 **`ServerLevel.destroyBlock(pos, true, owner)`**。没有 `removeBlock`、`setBlock(AIR)` 或 `drop=false` 分支，也不额外调用 `Block.dropResources`、`playerDestroy`、`Containers.dropContents` 或手动复制库存物品。只跳过空气和纯 `LiquidBlock`；含水实体方块仍可正常毁块，并由原版恢复其 fluid state，避免把所有含水容器又变成隐含保护。

本机 1.21.1 源码已核对：`Level.destroyBlock` 产生破碎 `levelEvent 2001`，读取 block entity 并调用 `Block.dropResources`，再替换为原生 fluid legacy state，成功时发送 `BLOCK_DESTROY`。`Block.dropResources` 走正常 loot／NeoForge block-drop hooks；普通方块 `popResource` 尊重 `doTileDrops`。箱子的 `onRemove` 自己调用 `Containers.dropContentsOnDestroy`，潜影盒由其原版 loot／内容组件路径保留内容，不再手动散落一次。

**世界掉落规则按 Minecraft 原生语义保持：**`doTileDrops=false` 会控制普通方块 loot，箱内库存的原版 `Containers.dropItemStack` 路径却直接 `addFreshEntity`，不受该 gamerule 控制。因此 false 时箱内库存仍可散落；这里不增加 EntityJoin 拦截、库存清空或其它覆盖原版行为。无掉落回归使用纯泥土，不声称 false 会吞掉库存。

`destroyBlock` 使用原版 `ItemStack.EMPTY` 工具参数，不是替玩家虚构钻石镐、精准采集或时运。需特定工具／loot 条件的方块最终掉落由其原版表决定。容器内容与方块本体 loot 各走一次原生路径，避免双份物品。

## 玩家开关与服务端归属

读取服务端玩家附件 `ModAttachments.SKILL_SETTINGS.bulletdiveBlockBreaking()`。关闭时 `begin` 不创建任务，并取消该玩家已存在的活跃任务；待处理任务每 tick 检查开关，在真正毁块前及保护事件回调后也重新检查。关闭只停止后续地形处理，不倒退已经发生的真实毁块。默认值、持久化、死亡复制与同步由 `SkillSettings` 附件负责，本文件不重实现网络设置。

`begin` 强制服务端线程；Job 持有真实 `ServerPlayer` 和 `ServerLevel`。每 tick 核对玩家存活、感染／原型模式、已学技能、建造权限、移除状态和所属世界，登出、死亡、换维度及服务器停止清理任务。高度／落点是服务端控制器的实际落差与碰撞结果；本次不新增从客户端接收高度、能量或待破方块坐标的接口。

现有状态、方块破碎事件、掉落实体由 Minecraft／NeoForge 正常广播；禁止把客户端预测画面当服务器已经毁块或已经命中的依据。专用服务器无需访问客户端渲染类。

`Plan.budget` 与 `Snapshot.visited/destroyed/protectedBlocks/skipped` 已改为 long；半径、深度和实际最大深度保留 int，既有控制器通过 `begin` 与 `snapshot` 读取。`visited` 记录实际逐块检查，不把区块前沿探测或跳过的整列层数伪算为已检查方块。

本轮没有运行 Gradle、启动／关闭游戏或操作人类未保存存档。真实 LOW→HIGH→PROTECTED→DISABLED→CANCELPENDING→NODROPS 的服务器回归应顺序执行，避免同 owner 的新任务把上一项覆盖。仍需实际验证专用服务器启动、两端同步、开启后箱子恰好一份本体和原数量库存、纯泥土 `doTileDrops=false` 零物品、保护事件取消／不可破坏方块、关开关取消后续任务，以及高落差掉落负载和 server tick 时间；结果由集成实测记录，不以本轮纯测试代替。
