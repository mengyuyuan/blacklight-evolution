# 建筑组织：多维度附着、材料同化与退化

## 当前对象

按 2026-10-27 用户纠偏，本轮处理的是地形和建筑上的组织群：原有连续肉柱、依附楼体的支撑和跨楼桥索，以及由这套建筑组织生成感染生物。
不是扩展独立的 `BlacklightHive` 战斗实体。误走方向的未提交代码已经撤出，单独保存在 `E:/Blacklight-Completion-20261027/deferred-entity-hive-WIP-110640`，不进入构建或交付。

原有路径仍依据实际楼体支点生成，保留每处稳定的形态、曲线、分支、实体碰撞、跨街锚点和断支记录。支撑表现使用真实碰撞及方块附着面，楼体仍遵循 Minecraft 的方块规则。

## 本轮实现

成熟附着皮层现在能逐步同化它实际接触的建筑块，每块支付 3 份已有养分，转成保持实体支撑面的甲壳或囊组织。每次仅处理一个接触位置，和表面生长、肉柱、老化、清理共用维度工作预算。
不从石头铸造食物，不从远处坐标搜索或强制生成区块。普通食物、消化与生物输送继续使用既有真实供养路径。

- 要有真实成熟附着点、实际加载并模拟的接触块、足够养分及有效建筑组织生长源。
- 全实体可破坏建筑块采用通用检查；含物品栏的方块、不可破坏块、液体、生成器和本模组已有组织不会被这条材料同化路径抹去。
- 末地石不因属于“末影龙不可破坏”标签而意外免疫；下界和其他维度使用各自实际方块、边界和存档。
- 自然放置保护事件可以否决。同化回滚原方块并退费；同维度事件回调不能递归领取新工作预算。
- 原材料按方块状态调色板保存，保留例如柱体轴向。每个组织最多记录 8192 块和 256 种原状态，不增加逐块方块实体。

## 建筑孵化

成熟建筑组织仍按世界和地方阶段选择感染生物，支付已有养分并占用共享人口与出生预算。
本轮新增出口检查：除出生身体不碰撞外，还要有至少两格、与体型相适应的无碰撞且有地面支撑的通行空间，跳过肉柱内部的封闭小空隙。
检查只读已加载的整身范围，不为寻路或出口加载新地形；没有安全位置就保留材料与已完成育成工作。

同一建筑在实体加入事件之前预留一次育成工作。外部回调不能重用；否决或异常退款，源在回调中被清除时不能留下幽灵出生。
这属于建筑组织入口，既有独立实体母巢保留兼容行为。

## 清除和保存

移除实际生长源后，组织不再生产。记录的墙体材料逐项恢复，实体柱体从高处与末端逐步退出，再清理附着皮层。
每一步同样受维度预算、实际模拟范围、游戏规则和保护事件约束；卸载处保留待处理记录，不强行加载。
玩家后来替换成其他方块或已经挖掉的位置保持现状。只对仍等于本次组织结果的原材料位置恢复原状态。

死亡组织的原材料调色板、实体路径、附着坐标和清理进度保留到退化结束，不能一保存就丢掉待清理身体。
旧存档无材料记录不会补造资源；已清剿位置保留重生保护。活动和待清理记录合计最多 64 处，活动数量仍受既有配置控制。

服务器配置为 `world/serverconfig/blacklight-building-infection-server.toml`：

- `assimilateBuildings` 控制新增墙体同化。
- `buildingBiomass` 控制肉柱体积生长。
- `workBudget` 保持每维度、每五 tick 的共同工作上限。
- `mobGriefing=false` 暂停本轮材料同化和自动恢复。

## 尚未等同于完整生态完成

用户追加要求：随时间自然扩散，后期整体看起来像生物。architecture.1 时 `activeTicks` 只在真实库存足以支付维护时推进，新建立的空仓核心不能靠时间自动发育。
后续用户明确“吞噬并占住即可长出搏动组织、持续出怪，可被子弹俯冲清理”，据此新增自动占领产能和局部搏动器官；实现与边界见 `LIVING_BUILDING_ZH.md`。
桥索到达干净远端楼体后自动建立生长点仍未接通，因此不能称为“随时间自然吞噬城市完成”。后续验收需覆盖实际连接、远端落点生根与继续扩散的连续流程，不能预置远端成熟附着点代替。

后期形态以有结构的活体建筑群为目标：粗主干连接根部与楼体，分支索沿实际支点输送，厚层组织包覆楼体，孵化囊沿供养结构分布，并有与生长、供养和生产对应的动态表现。
新增器官与体积必须由生长阶段和实际结构决定，保留建筑轮廓、可通行空间和方向差异；不以无序叠加方块或单纯把所有柱子放大作为最终形态。
这一段是新增验收标准，尚未实现和验证，不能计入本批已完成项。

未感染楼体沿完成桥索自动建立新附着点、断桥后的分区供养、更多自然资源输入、完整默认时间流程、双城全域和多人长期生态仍须接着完成。
