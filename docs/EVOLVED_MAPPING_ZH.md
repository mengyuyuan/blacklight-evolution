# 进化者偏向映射与六次成熟吞噬

依据用户 2026-10-26 的新要求实现，2026-10-27 连续验收。仅 NeoForge 1.21.1。

## 进阶条件

感染宿主完成至少六次**亲自成功结算**的成熟同类吞噬，已取得至少六个成熟供体器官，
并完成所有新器官/供体结构的整合后，才进入人形进化者蜕变。
同种器官可以重复，不要求六种不同器官。取消、拒绝死亡、重复回调、卸载或他人的吞噬都不增加次数。
幼体仍需先长成完全发育的感染体，不因凑次数跳过成长。

不再额外要求四类旧器官都达到 300 强度或同化积分达到 1000。
原有积分、器官强度和来源仍保存并用于成长，不删除旧存档记录。

## 三层映射

配置：`data/blacklight/blacklight/evolved_mapping/default.json`，可由服务端数据包覆盖。

1. **器官 ID → 偏向权重**：72 个设计 ID 已预留映射。仅实际实装、已继承、成熟且完成整合的器官参与计算。
   这不意味着 72 种器官均已制作；当前运行器官仍为 12 种。
2. **偏向分数 → 最高偏向集合**：按已整合成熟器官强度乘表中权重求和。出生器官的年龄不能盖过实际吞噬偏向。
   分数先按最大器官强度统一归一化，保持相对比例并防止极端数值溢出。
3. **最高偏向 → 进化者候选池**：只让匹配最高偏向、且运行实现已接入的候选参与权重随机。
   多个最高偏向并列时共同参与；低分偏向即使权重很高也不能抢选。

八类偏向：力量、重甲、掠食、刃化、触须、机动、感知、供养再生。

例子：六次吞噬均获得成熟骨刃，刃化最高，则只从刃化候选池选择。
四次甲壳与两次颅颚，仍按实际继承强度判断，不能只按吞噬次数猜测谁更强。

## 当前只有一种实际进化者

现有实际类型为 `blacklight:blade_evolved`，对应已接入的方块人、替换武器臂、二代动作与战斗控制器。
其他偏向还没有对应实体时，明确回退到这一种，仍保存真实最高偏向与 `Fallback=true`。
不能将回退称为已经制作了八种不同进化者。

以后增加类型：先做好模型、骨骼/动作、战斗逻辑和运行分派，再把其稳定类型 ID 注册到
`EvolvedMappingReload` 的可用类型集合，并在表里增加候选、匹配偏向和随机权重。
仅添加一个尚无运行实现的 JSON 名字不会让它进入抽选，避免生成无模型或无 AI 的敌人。

附加表放在 `data/<命名空间>/blacklight/evolved_mapping/*.json`；内建 default 层先读，其他层按稳定资源 ID 顺序合并。
每层使用 schema 1，声明所用偏向标签、局部器官权重、候选及该层有效 fallback。
最终 fallback 保留首层选择；要更换默认回退可覆盖内建 default 资源。
无效权重、未知偏向、重复候选或不可用的最终回退会令该次重载失败，不部分发布一张坏表。

## 选定后不乱变

第一次实际开始蜕变时选定，保存在宿主 `BlacklightHost.EvolvedChoice`：
`Form`、`Type`、`Bias`、表 SHA-256、选择种子、是否回退及全部得分快照。
身体承诺、动画完成、存档重读继续保留这份选择；显示或渲染时不抽签。
蜕变被空间阻挡并回退后，再次尝试继续使用原选择。
已经变成进化者的旧存档保留原形态，不为补新字段擅自随机换型。

验证：纯规则测试覆盖最高偏向、并列、同偏向多候选、不可用类型、极端数值、72 个预留 ID 与存档快照。
实际服务端另验六次真实混合吞噬、六次成熟骨刃吞噬、完整蜕变、保存恢复与真正的服务器数据包重载。
