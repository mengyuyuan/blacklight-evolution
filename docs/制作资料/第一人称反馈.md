反馈由服务端同步的弹匣和WeaponReadyAt变化驱动，不根据按键推断开火。同武器同槽、时间未倒退，弹匣下降且readyAt前进才可能生成shot；弹匣增加且readyAt仍在装填窗口才生成reload。切枪/切槽、换世界/玩家、菜单/暂停/第三人称、变身/伪装/吞噬控制等会重置或隐藏状态；空仓、冷却失败不应凭空产生新shot。具体包延迟窗口和重装条件以FirearmViewState原文为准。

两手在同一观察帧完整交换不同快照时，同时重建观察基线，避免同型号不同弹量被误判为shot；单手真实射击恰好匹配另一手快照不抑制。跨tick分裂且与真实射击完全等价的数据仍无法无歧义区分；该有限视觉边界不修改库存、伤害或射击授权。

## 当前反馈公式原文

```java
double age = now - shotAt;
        float recoil = age >= 0 && age < 8 ? (float) Math.pow(1 - age / 8, 2) : 0;
        double remaining = reloadEnd - now;
        float reload = reloadDuration > 0 && remaining > 0 && remaining <= reloadDuration
                ? (float) Math.sin(Math.PI * remaining / reloadDuration) : 0;
        return new Frame(recoil, reload);
```

## 当前第一人称附加变换原文

```java
pose.translate(-sign * .13, .035 - frame.reload() * .11, frame.recoil() * .065);
pose.mulPose(Axis.XP.rotationDegrees(frame.recoil() * 4.5F + frame.reload() * 8));
pose.mulPose(Axis.ZP.rotationDegrees(sign * frame.reload() * 7));
```

视觉枪口与命中射线分离：命中仍从原始eye-.18射线起点求交，视觉枪口向方向前移的源码参数为 `['.95']`；示踪粒子loop原文 `['for(double t=2.5;t<start.distanceTo(end);t+=2.5)']`。避免贴脸大粒子和原版挥手遮挡的实际效果仍需GL实机核对。

完整源与display：[client-presentation.json](data/client-presentation.json)，FirearmViewEvents/State、FirearmItem、FirearmsCombat和八个物品模型均有sources快照/hash。静态枪模图只画原JSON几何及面UV，不套第一人称display，不能拿它判断不同FOV/左右手视角。
