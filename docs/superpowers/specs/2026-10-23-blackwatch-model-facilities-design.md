# 黑色守望模型与军事设施：增补设计

日期：2026-10-23。状态：独立 builder 检查通过；用户已明确“按设计直接实现，细节由你决定”，实施中。本稿增补已批准的战术小队设计，不重做已通过的行为。

## 意图、现状与选择

用户新增要求：模型、动作和军事设施也做；瞄准、射击、换弹表现可以暂缓或简单处理。沿用 Minecraft Java 的 NeoForge 1.21.1 与 Forge 1.20.1 两条独立分支。以下布局、人数和美术细节由实现者提出，不声称是作者或原作的既定设定。

两端现场已有：原版立方体 `BlackwatchModel`、64×64 原创纹理、普通/重装两个实体 ID、四阶段基础持枪姿态；25×25×9 哨站模板、原生 jigsaw 自然生成、5 名持久驻军、两个科技箱、军用电路掉落与野战扫描仪配方。哨站当前间距 32 / 分离 12 区块，限定平原、向日葵平原、热带草原、沙漠、积雪平原。不能把这些入口当成空白功能重做。

考虑的实现方向：

| 方向 | 收益与代价 | 建议 |
| --- | --- | --- |
| 完善现有立方体模型与数据模板 | 保持 Minecraft 风格、平台差异少、无新依赖；精细度受方块几何限制 | 本稿推荐 |
| 另建骨骼模型、完整动作和大型基地系统 | 动作自由度更高；引入新的资产管线和更多世界生成、玩法设计 | 留到维护者提出明确需求后 |

## 玩家可见结果

### 1. 士兵外观与简单动作

- 保留现有原创纹理和代码模型管线，细化头盔帽檐、独立护目镜、面罩及左右滤罐。普通兵增加背心弹匣袋、腰带、膝部护具、背包与通信天线。
- 重装兵使用更厚的肩甲、胸甲、腿甲和供弹背包，枪械加厚机匣、加长护筒，与普通兵的步枪有明显轮廓区别；不改变碰撞箱、伤害、射程和掉落。
- 沿用服务端 PHASE 0/1/2/3，仅细调闲置持枪、双手瞄准、轻微后坐及换弹时左手靠近弹匣的姿态。可以保留简单效果，不制作完整骨骼动画、弹匣物理或新网络协议。
- 输出可复现的本地几何预览，供检查装备轮廓。几何预览与编译不能代替 Minecraft 客户端实机观感验收；没有运行客户端时必须明确标注。

### 2. 哨站与检查站

- 完善现有 25×25 哨站：保留入口、掩体、营房、军械区域和可攀爬瞭望塔；补充床铺、补给区、可读的中英文标牌，修正可证实的通行或站位问题。原有 4 普通兵 + 1 重装兵与两个科技箱保留，新增一个补给箱。
- 新增 17×17、最高 9 格的小型检查站模板：中间为通行车道，两侧有路障掩体、警戒岗和小型补给棚。预置 2 普通兵 + 1 重装兵，均使用现有实体；1 个科技箱、1 个补给箱。
- 两种模板进入既有 `blacklight:blackwatch_outpost` 池，建议权重为哨站 2、检查站 1。继续使用原结构 ID、自然生成间距、群系和原生旋转；玩家可用同一个 `/locate structure blacklight:blackwatch_outpost` 寻找其中一种。
- 模板驻军只随原生结构放置生成一次；持久化、自动编组和驻守中心沿用已完成的小队实现。没有无限补兵、刷怪笼、定时扫描或强制加载区块。已有区块中的建筑不自动替换；新内容在新生成区块中出现。

### 3. 战利品循环

- 保留科技箱的 3–6 个军用电路及原材料、士兵原掉落和扫描仪配方，保持现有获取链。
- 新增 `blacklight:chests/blackwatch_supplies`，只放原版食物、火把和少量铁等野外补给。确切权重和数量由实现者确定，记录在数据文件；不加入新的枪械物品、弹药经济或血清奖励。
- 标牌提示军用电路可以制作扫描仪、扫描仪识别附近感染者；没有新的任务系统或额外合成链。

## 实施边界与错误处理

修改集中于客户端模型、原创结构生成脚本与 NBT、池/战利品/语言数据、专项验证与说明。两端分别使用 `structure`/`structures`、`loot_table`/`loot_tables` 等真实版本目录。仅在实际验证暴露缺陷时调整必要的既有入口，并记录原因。

世界生成使用原版 jigsaw 模板和已注册方块/实体；不新增自定义方块或世界生成 Java 事件。放置需检查四种旋转下驻军脚底支撑、两格头部空间、门口/梯子和箱子可用性。保留原资源 ID，使旧世界可加载。

源代码和新资产依项目 GPL-3.0-only 交付；不引入游戏提取或第三方模型。保持两个独立功能分支，新增依赖为零。不自动提交、推送、创建 PR 或发布。

## 验证与交付

1. 先增加真实服务端设施测试，覆盖原生池放置、两种模板驻军数量/兵种/支撑、旋转放置、科技与补给箱可生成战利品，以及扫描仪配方/结构池实际注册。旧数据应因缺少检查站/补给入口或新布局而失败，然后实现。
2. 两个平台独立执行新增 GameTest，连同已有 15 项规则测试和 17 项小队 GameTest 做定向回归。设施测试不依赖假的实体集合或仅搜索源码字符串。
3. 正常 `clean assemble`，检查客户端模型编译、最终安装 JAR、版本目录与 QA 资源排除；保留两端构建日志和 SHA-256。
4. 整体独立代码审阅一次，重点检查资源 ID、世界生成兼容、驻军生命周期、未验证的客户端问题与小队边界；只对有实际影响的问题补回归修复。
5. 提供两端可安装 JAR、依赖说明、源改动补丁、模型/布局预览和已有验证记录的更新。独立服务端验证不代表真人多人联机、整合包兼容、广域自然生成或客户端观感已验收。

由实现者决定：各立方体尺寸/UV 采样、床铺/补给家具的坐标、原版补给条目的精确权重、预览工具形式、测试夹具位置。任何改变上述玩法范围的决定需要在记录中说明。
