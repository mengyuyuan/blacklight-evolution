## 1. 用户意图与已确认范围

用户参与 Blacklight: Ascension 的黑色守望部分，已选择先做“战术小队”。目标平台为 Minecraft Java 版的 Forge 和 NeoForge。作者尚未提供具体任务清单。

目标是让已有黑色守望士兵形成可以观察、交战和逐步破解的小队：平时结伴巡逻，发现威胁后共享情报，交替射击与换弹，失去目标后回到巡逻。玩家应能利用掩体、伪装、近身抓取和吸收制造机会。

本文的首期行为、人数和时序参数是设计建议，不是作者已确认的设定，也不声称来自《虐杀原形》原作。用户确认本稿后，才作为本次实现的验收范围。

## 4. 玩家可见的首期行为

### 4.1 自动成组与巡逻

- 同维度、已加载、存活且未感染的现有普通兵和重装兵可以自动成组；每队最多 4 人，2 人起具有协同。单兵仍可独立行动。
- 不生成额外士兵。现有刷怪蛋、指令和自然生成得到的实体都能参与；保留两类实体的 ID、基础属性与掉落。
- 初次服务器 tick 为没有记录的士兵设置“驻守点”。该位置保存在实体 NBT 中，旧档实体可直接初始化。成组时使用队长的驻守点作为本队中心。
- 在队长 16 格内发现可加入的成员。队内成员及队长按稳定顺序分配，已有小队不因另一队经过而不断合并重排。无队士兵可加入附近未满小队。
- 队长在驻守点 12 格内选择能由原生导航到达的巡逻点，其余成员以疏散队形跟随。队形允许因门口、坡道和狭窄地形暂时散开，不传送纠位。
- 巡逻点和跟随点要有可站立地面，避开明显的落空位置与导航不可达点。寻路失败时降低重试频率，等待或重选；不破坏方块、开辟路线或强制加载区块。

### 4.2 发现威胁与情报共享

- 保留现有索敌范围、感染分类、报复及伪装规则。新增共享不是额外的敌对判定来源：来源成员必须已由既有规则取得合法目标。
- 小队只共享由成员实际看见、或由既有受击报复提供的威胁信息。接收者必须重新检查目标的存活、维度、创造/旁观、友军和 `DisguiseSystem.fooled` 结果。
- 共享范围以情报来源成员为中心，最多 32 格，并限制在本队；不向其他小队或全图广播。
- 对接收者仍有效的伪装不能被共享直接揭穿。小队系统不修改伪装身份或暴露值，不创建新的通缉、识破或悬赏规则。
- 共享记录包含目标 UUID、最后合法观察位置和观察时间。没有视线的成员只能向最后位置搜索；不得读取目标实时坐标来穿墙追踪或开火。
- 只有真实观察或新的合法受击事件能刷新情报时间。成员之间转发不能延长寿命，避免相互续期导致永久追捕。

### 4.3 交替射击与换弹

- 在现有瞄准 → 三连发 → 换弹周期上加入开火名额。2/3/4 人队同时最多允许 1/2/2 名可战斗成员处于瞄准和射击阶段；单兵保持自己的正常周期。
- 使用轮转队列分配名额。三连发结束后释放名额并进入原时长换弹，其他已经准备好的成员接替。无视线、无合法射线或被控制的成员不阻塞队列。
- 名额只决定谁可以开始一个完整周期，不能跳过换弹或补发被打断的子弹。对仍有视线且持续具备射击条件的成员，轮转应保证最终获得机会。
- 等待名额或换弹的成员可在小范围寻找可达的射击站位，与队友保持间距。首期使用原生导航和有限候选点，不做完整掩体评分、包抄地图或爆破系统。
- 开火当 tick 再检查目标合法性、控制状态、方块遮挡和友军挡线。友军挡线时不开火；不扩大伤害、射程或子弹穿透能力。
- 目标过近时选择安全后退点；无法后退时留在可站立位置。优先保留玩家突进抓取和利用换弹窗口的机会。
- 客户端仍按现有 `PHASE` 渲染，首期无需新网络协议、UI、模型、音频或动作资源。

### 4.4 搜索、脱离与归队

- 没有新的合法情报后，最多搜索 100 tick（正常 20 TPS 下约 5 秒），然后清空共享目标并返回巡逻中心。
- 超过距本队驻守点 48 格的追击边界时，不继续追逐，转为归队。共享情报不扩大这条边界。
- 目标死亡、移除、跨维度，或对该士兵成为友军/有效伪装时，该士兵立即停止攻击，不等待搜索超时。
- 成员被抓取、吸收、投掷或其他现有控制逻辑接管时，暂停巡逻、队形和开火，立即释放名额。现有 `ConsumeVisual.active()` 和控制权接口按语义使用，不仅在进入 Goal 时检查。
- 控制解除后重新确认目标并完整瞄准，不补发中断期间的攻击。小队不接管抓取位置、吸收奖励或投掷弹道。
- 队长死亡或失去可行动资格时，由有效成员接任，保留本组当前驻守中心。成员卸载、移除或被感染后退出人类小队。
- 连续 100 tick 距当前队长超过 32 格的成员离队；可回到自己的驻守点，并在满足条件后重新成组。不能为了保住队形强加载区块或传送实体。

## 5. 数据、模块与实现边界

以下是模块职责建议，具体类名和方法签名交由实现者决定：

1. **士兵实体/Goal 接入层**：调用已有目标、视线、伪装、控制权和导航接口；管理现有视觉阶段；所有伤害继续在服务端发生。
2. **小队协调器**：每个 `ServerLevel` 独立持有队伍、成员、共享情报和开火名额。不得跨服务器或维度共用一个静态队伍表。
3. **决策与时序规则**：人数上限、成员顺序、名额轮转、观察超时、追击边界等尽量与平台事件隔开，便于两端复用和针对性验证。不能为本次小队创建通用 AI 框架。
4. **平台生命周期接入**：按各分支现行 NeoForge/Forge API 处理移除、世界卸载与服务器停止，保持各自附件/capability 访问方式。

驻守点是唯一新增持久化数据。小队 ID、成员表、目标记忆、轮转队列和射击许可均为服务端临时状态；实体卸载或重启后根据当前加载的实体重新成组，允许队长和编组与离线前不同。每个成员原有驻守点不因加入其他人的小队而被覆盖；重组后采用新队长的驻守点。旧版本读取时可忽略新增的驻守点键，不宣称跨 Minecraft 版本存档可以回退。

成组只查询附近已加载的黑色守望实体；不扫描整个维度或所有生物。无队成员的邻域发现最多每 20 tick 一次，活动小队常规协调最多每 10 tick 一次；死亡、抓取和开火合法性每 tick 或在对应事件即时处理。导航刷新设定冷却，禁止每帧重建路径。卸载时清除相应引用，避免静态表保留整个世界。

本期不增加兵种、超级士兵、直升机、坦克、基地、实验室、研究科技、指挥菜单、玩家招募、全局警星或全套美术替换。自然生成与设施刷怪数量保持既有规则。

## 6. 参数与留给实现者的决定

首期建议参数统一放在一处，避免散落的魔法数：队伍上限 4；成组半径 16 格；巡逻半径 12 格；共享/脱队距离 32 格；搜索与脱队超时 100 tick；追击驻守半径 48 格。以上均待本稿确认和实际效果验证，不称为已完成平衡。

队形槽位、有限站位候选数量、路径失败的重试退避、UUID 比较实现、单元测试隔离方式、日志细节和类名由实现者决定。实现必须满足本文的可见行为及性能边界；若现有代码或实际场景证明需要改变人数、暴露规则、敌对范围、持久化范围或首期内容，应先更新本稿说明原因。

## 7. 验证方案与完成条件

以下是拟执行的验证，不是已经通过的结果。仓库常规构建默认仅运行 `assemble`；本稿确认时需同时确认执行下列定向单元/独立服务端验证。真实客户端试玩、真人联机与性能结论必须分别记录，不能用构建或模拟场景代替。

| 场景 | 预期结果 |
| --- | --- |
| 1/2/4/5 名士兵、混合重装兵 | 上限 4、无重复归属；单兵可独立交战；第 5 人不超额加入 |
| 巡逻遇到门口、障碍和高差 | 队形可暂时散开；不传送、破块或导航走向落空点 |
| 一人发现感染目标、同队有人无视线 | 有效情报只传本队；无视线者向最后位置搜索，不隔墙射击 |
| 有效伪装、目击暴露、重新隐藏 | 共享不绕过现有伪装判定；暴露与解除沿用现有系统 |
| 未感染普通玩家及直接攻击者 | 普通玩家不被平白标敌；现有直接报复仍有效 |
| 多人队连续交战 | 名额不超限，周期不被跳过；可战斗成员能轮到，换弹窗口存在 |
| 方块与友军挡线、盾牌防御 | 不穿墙、不误伤友军；继续走现有投射物防御结算 |
| 士兵在瞄准/射击/换弹时被抓取、吸收、投掷 | 立即让出移动和攻击控制权、释放名额；解除后不补发攻击 |
| 目标消失、跨维度、超过边界或情报过期 | 清理目标，停止开火并归队；转发不刷新观察时间 |
| 队长死亡、成员离队、感染和卸载 | 接任/清理正确，无永久占用名额或残留实体引用 |
| 存档重进、旧档实体无驻守点 | 安全初始化/读取驻守点；临时编组重新建立 |
| 世界卸载、服务器停止、两个维度 | 状态独立且可清理；不请求加载额外区块 |

验证先覆盖独立的规则与时序，再在独立服务端场景核对实体、目标、导航和生命周期接入。两端分别使用正确 JDK 和 Wrapper 执行 `assemble`，核对安装 JAR 不带 QA 类和测试世界，保留既有动作/模型资源。Forge 使用适当重混淆后的安装产物。

交付记录应包含两个平台各自的提交/未提交状态、构建与定向测试日志、可玩安装包路径及 SHA-256、实际执行的场景和未验证项。如果本机网络或依赖阻止构建/服务端验证，报告具体阻塞，不能将源码检查称作可玩交付。
